# Plans et bilans des séries

Plans validés par Benoit et bilans de fin de série. L'état actuel du projet est
résumé dans [`../../memory/README.md`](../../memory/README.md).

| Document | Rôle |
| --- | --- |
| [`ecosystem-rebuild-plan.md`](ecosystem-rebuild-plan.md) | Plan de refonte de l'écosystème validé le 2026-10-10 : API fichier `Hack*`, manifeste en classe C#, paramètres et journaux en fichiers, `/proc` et `/dev`, shell complet, corbeille, permissions dangereuses, apps de base. **À lire en premier.** |
| [`execution-isolation-plan.md`](execution-isolation-plan.md) | Phase 5, validée et terminée le 2026-10-16 (vérification finale `rebuild/5-final`) : mesure optionnelle du CPU et de la mémoire par processus, « Not responding », arrêt propre (`StopRequested`, `CheckpointAsync`, escalade), processus sans interface dans des Web Workers ; chantiers `rebuild/5-*` et migration des apps existantes (ADR 0066 à 0071). |
| [`execution-followups-plan.md`](execution-followups-plan.md) | Suites de la phase 5, **validé le 2026-10-17**, à exécuter après la migration wasm v3 : limites par processus, OOM killer désactivé par défaut, passerelles distantes d'événements, boîte « L'application ne répond pas », tâches lourdes en worker (`HackBackground.RunAsync`) puis essai de fenêtres en worker, `HackerOs.Server` servi en WebAssembly avec son API seule côté serveur, isolation cross-origin (COOP/COEP) ; chantiers `exec/*` et réponses de Benoit ; branche `exec/base` créée le 2026-10-18, ADR 0124 à 0135 écrits, réponses de Benoit aux questions E1 à E4 (section 6.1) ; **série terminée le 2026-10-18** par `exec/10-final` (SDK 1.2, vérification finale en section 11), puis fusionnée dans `main` le même jour. |
| [`desktop-and-context-menu-plan.md`](desktop-and-context-menu-plan.md) | Icônes du bureau, contrôle de fichiers et menu contextuel central, **validé le 2026-10-19** : SDK réduit à des contrats (l'OS fournit le rendu à l'exécution, l'explorateur s'inscrit comme fournisseur du contrôle de fichiers et de ses dialogues), menu contextuel multi-niveaux fourni par l'OS (`Menus.Attach`), entrées de menu inscrites par les apps à l'installation (`[RegisterFileContextMenu]`, placement, capacité `shell.context-menu`), bureau sur `~/Desktop` en grille avec positions et fichiers `.desktop`, SDK 2.0 qui retire `FileView` ; réponses Q1 à Q22, ADR [0148](../adr/0148-sdk-contracts-and-os-provided-controls.md) à [0152](../adr/0152-desktop-icons.md) écrits, chantiers 0 à 6 tous faits ( [0155](../adr/0155-file-control-implementation-adjustments.md) pour le 3, [0157](../adr/0157-file-dialogs-show-the-file-control.md) pour le 3b, [0158](../adr/0158-replaceable-file-provider-implementation-adjustments.md) pour le 3c, [0159](../adr/0159-app-menu-entries-implementation-adjustments.md) pour le 4, [0160](../adr/0160-desktop-implementation-adjustments.md) pour le 5, [0161](../adr/0161-sdk-2-0-implementation-adjustments.md) pour le 6) ; vérification finale de la série au §13. |
| [`asp-hack-plan.md`](asp-hack-plan.md) | Phase web, validée le 2026-10-16 (branche `web/base`) : sites internes ASP.Hack façon ASP.NET MVC, sites Blazor interactifs, sites statiques gérés par `hackwebd` et Web Server Manager, rendu HTML isolé du navigateur, `file://`, fenêtres détachées ; chantiers `web/*` (ADR 0073 à 0078). |
| [`wasm-v3-completion-plan.md`](wasm-v3-completion-plan.md) | Fin de la migration wasm v3, **validé et terminé le 2026-10-17** (branche `v3/base`) : ce qui reste de `doc/fr/wasm/dev/plans/wasm-v3-migration-analyse.md` en chantiers `v3/*` (fenêtres, intents, services, versions et paquets du SDK, sauvegarde, réglages sensibles, synchro, relais du serveur, Hack Paint et éditeur de thèmes, localisation, accessibilité, trimming, gel du SDK 1.0) ; **aucun jeu sur ce repository** (ADR 0135). |
| [`wasm-v3-final-status.md`](wasm-v3-final-status.md) | Bilan de la migration wasm v3 (chantier `v3/16-final`, 2026-10-17) : les seize chantiers livrés, la vérification finale de `v3/base` (build, toutes les suites, publication élaguée, compatibilité du SDK 1.0, trois hôtes), les lacunes connues, les questions encore sans réponse et les tests rouges préexistants ; complété par la vérification de `v3.1/base` après la publication du SDK 1.1. |
| [`v3-1-series-plan.md`](v3-1-series-plan.md) | Série v3.1 (branche `v3.1/base`, 2026-10-17) : lacunes de la migration v3 corrigées avant les suites de l'étape 5 ; restauration de la géométrie des fenêtres (ADR 0116), titre de fenêtre posé par l'app et publication du SDK 1.1 (ADR 0117), fusion de `v3/base` (associations par utilisateur, `passwd`), branches, dépendances et barre de fusion. |
| [`wasm-v3-migration-analyse.md`](wasm-v3-migration-analyse.md) | Analyse de la migration wasm v3 (point de départ du plan de fin de migration). Historique. |
| [`authentication-task-list.md`](authentication-task-list.md) | Ancienne liste de tâches de l'authentification WebAssembly. Historique. |
| [`hackeros-store.md`](hackeros-store.md) | Note pour la future app système **HackerOs Store** (façon Play Store) qui lira la liste du dépôt `Kazo-ca/HackerOs-AppMarketPlace` et installera par le service de l'ADR 0182 ; à reprendre quand des apps seront publiées. |
