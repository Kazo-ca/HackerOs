# Changelog

The changes of Kazo OS, by version. This file is generated from `wasm2/KazoOs/changes/` by
`wasm2/KazoOs/build/tools/collect-changes.sh` (ADR 0186): do not edit it by hand. Changes already
deployed but not released yet are in the Settings ▸ What's new page of the OS.

## 3.1.0 (2026-11-07)

### New

- **Apps open the files of your network drives.** The network drives you mount count as your personal files: an app allowed to read your files (filesystem.user-home.read) now reads them too, with no dangerous capability, and filesystem.user-home.write writes them. Another user's drive and /mnt itself stay system files, and the drive's permissions still apply. ([0231-network-drives-count-as-personal-files.md](doc/en/wasm/dev/adr/0231-network-drives-count-as-personal-files.md))
- **Child windows and dialogs for apps.** A window app can open its own windows with ShowWindowAsync and its own modal dialogs with ShowDialogAsync, like Form.Show and Form.ShowDialog in WinForms. The window's component derives from KazoWindowBase and closes with CloseAsync(result); it belongs to the same app and closes with its owner. ([window-model.md](doc/en/wasm/framework/window-model.md))
- **Frameless windows float on the desktop.** A window with the None style is transparent: a click where its app draws nothing reaches the desktop or the window below, so an app with its own skin can float on the desktop (issue #378). ([window-model.md](doc/en/wasm/framework/window-model.md))
- **Window styles inspired by WinForms, and apps that minimize their own window.** A window app can choose the Normal, Tool or None style and turn off its icon, its Maximize and Minimize buttons or its taskbar button, in its manifest or at run time. It can also minimize, maximize, restore, move and resize its own window (issue #384). The OS dialogs now use the Tool style, with Close only and no taskbar button. ([window-model.md](doc/en/wasm/framework/window-model.md), [0234-window-styles-inspired-by-winforms.md](doc/en/wasm/dev/adr/0234-window-styles-inspired-by-winforms.md))

### Improved

- **New illustrated app icons, shown everywhere.** The system apps have new colour icons that show what each app does. The Start menu, the desktop shortcuts and the explorer now draw each app's own icon, installed apps included, instead of one icon per category; an icon pack still replaces them. Apps can read the icon address with KazoAppInfo.IconUrl. ([0232-illustrated-app-icons-everywhere.md](doc/en/wasm/dev/adr/0232-illustrated-app-icons-everywhere.md))

### Fixed

- **A newly installed app can read your files right away.** An app installed with kazopkg or the Kazo OS Store only received its declared capabilities at the next sign-in, so its first launch was refused access to your files. The signed-in user now gets them as soon as the app is installed or updated; dangerous capabilities still need an administrator's approval. ([capabilities.md](doc/en/wasm/framework/capabilities.md))
- **File dialogs open on your home folder and never take the OS down.** An Open, Save or Select folder dialog asked without a start folder opened on /home/ followed by the user's identifier, which does not exist, and the OS crashed. It now opens on your home folder (/home/<login>); a missing or unreadable start folder falls back to your home folder, then to /. ([sdk-reference.md](doc/en/wasm/framework/sdk-reference.md))

### For developers

- **App repositories can tag a release from GitHub.** The kazoos-solution template has a Tag a release workflow: it tags a commit of main with the app's version and starts the two publishing workflows, so a person or an agent can release without pushing a tag from a computer. ([app-repository.md](doc/en/wasm/framework/app-repository.md))
- **Apps are signed only in the Kazo OS Store repository.** KazoOsPack no longer signs packages: the KazoOsKeyGen target, the KazoOsSigningKeyFile property, the generator's keygen and sign commands and the HACKEROS_APP_SIGNING_KEY variable are gone. The kazoos-solution template still publishes the kazoos-packages branch, unsigned; the secret can be deleted from app repositories. ([0219-app-authors-signing-tool.md](doc/en/wasm/dev/adr/0219-app-authors-signing-tool.md))
- **The kazoos-solution template has its launch profile again.** The rename to Kazo OS had dropped Properties/launchSettings.json from the host project of the kazoos-solution template. It is back, so dotnet run and Visual Studio start the host on http://localhost:5280 with the browser debugger. ([app-repository.md](doc/en/wasm/framework/app-repository.md))
- **The store workflow of the kazoos-solution template finds an existing fork.** publish-to-kazoos-store.yml guessed the fork as <author>/Os-AppMarketPlace. A fork made before the catalog was renamed keeps its old name, so the clone failed. The workflow now asks GitHub for the author's fork of the catalog. ([app-repository.md](doc/en/wasm/framework/app-repository.md))

## 3.0.0 (2026-11-05)

### New

- **Forgot password? Reset the machine from the sign-in screen.** When no password is remembered, the sign-in screen offers to erase Kazo OS in this browser and start over at the first-run setup, after typing ERASE to confirm. Whoever deploys the OS can turn it off with KazoOs:SignIn:FactoryReset:Enabled in appsettings.json. ([sign-in-factory-reset.md](doc/en/wasm/dev/sign-in-factory-reset.md))

### Improved

- **A factory reset leaves nothing of Kazo OS in the browser.** Resetting from Settings or from « Forgot password? » now also erases web site databases, installed apps' files, every cache, localStorage, sessionStorage, the origin private file system, cookies and the service worker, not only the OS database. ([0227-factory-reset-erases-everything.md](doc/en/wasm/dev/adr/0227-factory-reset-erases-everything.md))
- **Backups end in .kosbak, design tokens are --kos-*, diagnostics are KOS*.** The last short HOS names become KOS. New backups are .kosbak files; an older .hosbak backup can still be restored. The CSS variables of the design system are now --kos-* (with data-kos-* attributes and kos-* classes): a theme file or theme pack written with --hos-* is still read, and saved themes and settings are updated at the first start. Build diagnostics are now KOSAPP, KOSSDK, KOSWEB, KOSBG and KOSCHG, with the same numbers: update NoWarn and pragma lists. ([sdk-packages.md](doc/en/wasm/framework/sdk-packages.md))
- **Commands, files, app ids and settings take the Kazo OS names.** hackpkg becomes kazopkg and hackbackup becomes kazobackup (the old names still work and print a warning), app packages and theme packs use .kazoapp and .kazotheme (the old .hackapp and .hacktheme are still read), the OS files move to /etc/kazoos, ~/.config/kazoos and /etc/kazoweb, the store is called Kazo OS Store, ASP.Hack becomes ASP.Kazo and Hack Paint becomes Kazo Paint. The server and the PWA read the KazoOs configuration section and KAZOOS_ variables, and still read HackerOs and HACKEROS_. The dotnet new templates are now kazoos-window, kazoos-solution... App ids become org.kazoos.*, capabilities kazoos.*, and the browser databases, theme ids and caches take the kazoos and kazoweb names. ([sdk-packages.md](doc/en/wasm/framework/sdk-packages.md))
- **HackerOS is now called Kazo OS.** The name HackerOS was already used by a Linux distribution. The OS now shows the name Kazo OS everywhere: window title, installed app, sign-in screen, notifications and documentation. ([0228-rename-to-kazoos.md](doc/en/wasm/dev/adr/0228-rename-to-kazoos.md))
- **Kazo OS now lives at os.kazo.ca.** The site is published at https://os.kazo.ca/ and the original version at https://os.kazo.ca/legacy/. Links in the project point to the new address. ([github-pages-deployment.md](doc/en/wasm/dev/github-pages-deployment.md))
- **Your accounts, files and settings follow the move to Kazo OS.** At the first start of Kazo OS 3.0.0 in a browser used by an earlier version, the stored data moves to the new names before the OS starts: databases, settings, configuration files and app ids. Your documents are not changed. A backup made before 3.0.0 is migrated the same way when it is restored. ([rename-migration.md](doc/en/wasm/dev/rename-migration.md))
- **hackos.kazo.ca now leads to os.kazo.ca.** Every address on hackos.kazo.ca is redirected to the same address on os.kazo.ca. An app installed from hackos.kazo.ca clears its cache on its next opening and goes to os.kazo.ca, where it can be installed again. ([cloudflare-redirect.md](doc/en/wasm/dev/cloudflare-redirect.md))

### Fixed

- **An installed app finds its scripts after a Ctrl+F5 or an install made in another tab.** The service worker now takes over a page loaded with Ctrl+F5 when it runs the same release, and an open tab no longer removes from the shared cache the files of an app another tab has just installed. ([0225-serve-installed-app-files-to-every-page.md](doc/en/wasm/dev/adr/0225-serve-installed-app-files-to-every-page.md))
- **Kazo OS starts after a server error right after a deployment.** When the site briefly refused a system file (for example right after a new version is published), the boot stopped on « Kazo OS could not start ». It now retries by itself after 5, 15 then 30 seconds. ([0224-retry-the-boot-after-a-server-error.md](doc/en/wasm/dev/adr/0224-retry-the-boot-after-a-server-error.md))
- **Restarting to update works with several Kazo OS tabs open.** When another Kazo OS tab, screen or window was open, or after Ctrl+F5, « Restart to update » could still reopen an older version. It now activates the downloaded version first. ([0223-restart-onto-the-new-version.md](doc/en/wasm/dev/adr/0223-restart-onto-the-new-version.md))
- **The Kazo OS Store lists the official catalog's apps on an older installation.** An app-sources.config written before the [catalogs] section existed named no catalog, so the Kazo OS Store stayed empty. Such a file now gets the official catalog, verified; an empty [catalogs] section is still respected. ([app-installation.md](doc/en/wasm/dev/app-installation.md))

### For developers

- **SDK 3.0: the Kazo.Os.* packages and the Kazo* types.** Every package moves from HackerOs.* to Kazo.Os.* (Kazo.Os.AppSdk, Kazo.Os.Templates...) and every SDK type from Hack* to Kazo* (HackFile becomes KazoFile, HackerIcon becomes KazoIcon, and the HackIcon record becomes KazoSurfaceIcon). The version is 3.0.0: an app built on SDK 2.x is refused and must be rebuilt against the new packages. ([0228-rename-to-kazoos.md](doc/en/wasm/dev/adr/0228-rename-to-kazoos.md))
- **The Kazo OS Store workflow of the kazoos-solution template opens its pull request again.** The workflow no longer passes --remote to gh repo fork, which current gh versions refuse, and retries the clone of the fork while GitHub creates it. ([app-repository.md](doc/en/wasm/framework/app-repository.md))
- **The kazoos-solution template names its app project for the Kazo OS Store.** store/store.json of a new app repository has a project field, so the catalog builds the app's project instead of the whole solution, whose tests project has no KazoOsPack target. ([app-repository.md](doc/en/wasm/framework/app-repository.md))

## 2.2.2 (2026-11-01)

### Improved

- **Hack Store apps are signed.** HackerOS now checks the signature of every app from the official Hack Store and refuses a package that was not signed by the catalog or was changed after. ([app-installation.md](doc/en/wasm/dev/app-installation.md))

## 2.2.1 (2026-11-01)

### New

- **Set as wallpaper from the menu of an image.** Right-click a PNG, JPEG or WebP image and choose Set as wallpaper: it becomes the desktop background at once, without opening Settings. With several screens, a submenu chooses the screen. ([#330](https://github.com/Kazo-ca/Os/pull/330), [0218-set-as-wallpaper-file-menu.md](doc/en/wasm/dev/adr/0218-set-as-wallpaper-file-menu.md), [wallpapers.md](doc/en/wasm/dev/wallpapers.md))
- **Do not disturb.** A Do not disturb switch in the clock panel (the shade on a phone) and in Settings ▸ Notifications stops the notification bubbles and sounds, errors included. Notifications still go to the clock panel and the unread dot still shows them. A moon in the notification area says the mode is on; the choice is saved for each user in ~/.config/hackeros/notifications.config. ([0216-do-not-disturb.md](doc/en/wasm/dev/adr/0216-do-not-disturb.md))
- **Mouse Back and Forward buttons in apps.** The mouse Back button, Alt+← and the phone's Back (Android button or gesture, iOS swipe) now go to the active app instead of moving the browser tab back and leaving HackerOS; the mouse Forward button and Alt+→ go forward. On a phone, Back follows the ◁ button. Apps receive them through IAppBackHandler and the new IAppForwardHandler, with the new MouseButton and SystemBack sources. ([0220-mouse-back-forward-buttons.md](doc/en/wasm/dev/adr/0220-mouse-back-forward-buttons.md))
- **Wallpaper on the mobile home screen.** The mobile home screen can show an image too. In Settings ▸ Appearance ▸ Wallpaper, pick « Mobile », then an image and how it fits; the desktop keeps its own choice. Without an image, the mobile theme's background stays. ([0217-mobile-home-wallpaper.md](doc/en/wasm/dev/adr/0217-mobile-home-wallpaper.md))

### Improved

- **Frosted glass app drawer on the iOS theme.** On the iOS mobile theme, the app drawer is now the same frosted glass as the notification shade, so the wallpaper shows through. Other themes keep an opaque drawer; a theme can choose with --hos-mobile-drawer-background and --hos-mobile-drawer-backdrop-filter. ([0217-mobile-home-wallpaper.md](doc/en/wasm/dev/adr/0217-mobile-home-wallpaper.md))

### Fixed

- **Installed apps keep their look.** An app installed from the Hack Store or with hackpkg now loads its own styles and scripts, and looks the same as an app that comes with HackerOS. ([0221-pack-all-static-web-assets-of-an-app.md](doc/en/wasm/dev/adr/0221-pack-all-static-web-assets-of-an-app.md))
- **Installed apps speak your language.** An app installed from the Hack Store or with hackpkg now shows its French texts, as an app that comes with HackerOS does. ([0222-installed-app-satellite-assemblies.md](doc/en/wasm/dev/adr/0222-installed-app-satellite-assemblies.md))
- **Restarting to update opens the new version.** When a new version of HackerOS is available, it now downloads in the background, and « Restart to update » opens it instead of an older copy kept by the browser. Other open HackerOS tabs restart too, and the Start menu Restart also takes the new version. If the download fails, nothing closes and you are told. ([0223-restart-onto-the-new-version.md](doc/en/wasm/dev/adr/0223-restart-onto-the-new-version.md))

### For developers

- **App packages carry their satellite assemblies.** HackerOsPack puts the satellite assemblies of the app's own assemblies in the package at lib/<culture>/<assembly>.resources.dll; the OS checks them and loads them before the app's first render. ([0222-installed-app-satellite-assemblies.md](doc/en/wasm/dev/adr/0222-installed-app-satellite-assemblies.md))
- **HackerOsPack packs every static resource of an app.** The package now holds the whole wwwroot/, the collocated .razor.js files and the scoped CSS bundle, declared in the package's manifest with their SHA-256; the publish workflow of the hackeros-solution template copies that manifest into the catalog folder. ([0221-pack-all-static-web-assets-of-an-app.md](doc/en/wasm/dev/adr/0221-pack-all-static-web-assets-of-an-app.md))
- **Signing tool for app authors.** dotnet build -t:HackerOsKeyGen creates an author's signing key, HackerOsPack signs each package with the HACKEROS_APP_SIGNING_KEY secret, and the hackeros-solution template publishes the signed packages on the hackeros-packages branch on each version tag. Administrators require an author's signature by adding their public key to [signing-keys]. ([0219-app-authors-signing-tool.md](doc/en/wasm/dev/adr/0219-app-authors-signing-tool.md))

## 2.2.0 (2026-10-31)

### New

- **Window animations.** Windows now open, close, minimize into their taskbar button, restore, maximize and snap with a short fade and scale. The Reduce motion setting turns the animations off, and a theme can change their duration. ([#311](https://github.com/Kazo-ca/Os/pull/311), [0198-window-animations.md](doc/en/wasm/dev/adr/0198-window-animations.md))
- **Notification bubbles.** Each new notification from the OS or an app now shows as a bubble for 6 seconds, above the taskbar of the first screen or at the top of a phone screen, then stays in the clock panel. Pointing at a bubble keeps it open. A ready update arrives the same way, with its Restart to update button. ([#309](https://github.com/Kazo-ca/Os/pull/309), [0197-notification-toasts.md](doc/en/wasm/dev/adr/0197-notification-toasts.md))
- **Installable local server.** The HackerOS server installs on your computer as a service on Windows, Linux and macOS, or as a Docker image, from the archives attached to each release. It listens on this computer only, or also on the local network over HTTPS with a local certificate authority. Settings > Server connection > Local server lists the downloads, tests an address and pairs this device with a one-time code; apps get HackServerConnection.PairAsync and TestAsync. ([#308](https://github.com/Kazo-ca/Os/pull/308), [0191-installable-local-server.md](doc/en/wasm/dev/adr/0191-installable-local-server.md), [installable-server.md](doc/en/wasm/dev/installable-server.md))
- **Real sites in the browser through the HackerOS server.** With a HackerOS server connected, the Browser opens real web sites through its proxy and stays signed in to them (cookies and redirects are kept). An icon at the start of the address bar tells where the page came from, and http pages say Not secure. Apps get HackHttpResponse.Source and the TimedOut and BlockedByAdministrator network errors. ([#305](https://github.com/Kazo-ca/Os/pull/305), [0210-browser-real-sites-through-the-proxy.md](doc/en/wasm/dev/adr/0210-browser-real-sites-through-the-proxy.md))
- **System sounds.** The OS plays a sound for notifications, warnings, errors, sign-in and sign-out. Choose the sound theme (HackerOS or Soft), the volume or turn the sounds off in Settings > Sound. Add your own theme in ~/.local/share/sounds (freedesktop.org format, OGG or MP3). ([#304](https://github.com/Kazo-ca/Os/pull/304), [0204-os-event-sounds.md](doc/en/wasm/dev/adr/0204-os-event-sounds.md), [system-sounds.md](doc/en/wasm/dev/system-sounds.md))
- **Open a .zip as a folder.** A double click on a .zip file in the File Explorer opens it as a read-only folder, with its path in the address bar. A file opened from the archive is extracted to /tmp first. Dragging or pasting items out of the archive extracts them; renaming, deleting or adding inside it is refused. Double-clicking a .zip on the desktop opens it in the File Explorer. ([#302](https://github.com/Kazo-ca/Os/pull/302), [0185-file-explorer-improvements.md](doc/en/wasm/dev/adr/0185-file-explorer-improvements.md), [file-explorer.md](doc/en/wasm/dev/file-explorer.md))
- **Taskbar window previews.** Hovering a window's taskbar button shows a small live copy of the window, with a button to close it. Click the preview to bring the window to the front. Rest the pointer on it to see that window alone: the other windows of the screen keep only their outline. ([#300](https://github.com/Kazo-ca/Os/pull/300), [0199-taskbar-window-previews.md](doc/en/wasm/dev/adr/0199-taskbar-window-previews.md))
- **Taskbar context menus.** A right click on a window's taskbar button gives New window and the window menu with Other screen. A right click on the rest of the taskbar gives Task manager, Show the desktop, Cascade windows, Tile windows and Taskbar settings, for the windows of that screen. ([#289](https://github.com/Kazo-ca/Os/pull/289), [0194-taskbar-context-menus.md](doc/en/wasm/dev/adr/0194-taskbar-context-menus.md))
- **Start as a guest, then create your account.** On a new installation, Start as a Guest opens the desktop without an account. Create my account (sign-in screen, Settings ▸ Users or the Start menu) then makes it a real account with a password, keeping the guest's files or starting over. ([#286](https://github.com/Kazo-ca/Os/pull/286), [0187-guest-start-and-sign-in-credits.md](doc/en/wasm/dev/adr/0187-guest-start-and-sign-in-credits.md), [guest-account.md](doc/en/wasm/dev/guest-account.md))
- **The clock shows your local time.** The clock, the date command, ls -l and the apps now use your time zone: the device's by default, or one chosen in Settings > Date and time. Apps read it with HackTimeZone and IAppExecutionContext.TimeZone. ([#283](https://github.com/Kazo-ca/Os/pull/283), [0193-local-time-and-time-zone.md](doc/en/wasm/dev/adr/0193-local-time-and-time-zone.md))
- **Compress, Download, Copy path and Send to.** The File Explorer file menu can compress items, download them, copy their path and send them to another place. ([#275](https://github.com/Kazo-ca/Os/pull/275), [0185-file-explorer-improvements.md](doc/en/wasm/dev/adr/0185-file-explorer-improvements.md))
- **Drag files out of the browser to download them.** Drag items from File Explorer to your computer to download them; several items arrive as a .zip. ([#275](https://github.com/Kazo-ca/Os/pull/275), [0185-file-explorer-improvements.md](doc/en/wasm/dev/adr/0185-file-explorer-improvements.md))
- **Credits on the sign-in screen.** The sign-in screens and Settings ▸ About show the author and a link to the GitHub project. ([#262](https://github.com/Kazo-ca/Os/pull/262), [0187-guest-start-and-sign-in-credits.md](doc/en/wasm/dev/adr/0187-guest-start-and-sign-in-credits.md))
- **A taskbar on every screen and an "Other screen" menu.** Each screen can have its own taskbar. The window icon and the Maximize button offer to send a window to another screen, and a shortcut identifies each screen. ([#238](https://github.com/Kazo-ca/Os/pull/238), [0179-per-screen-taskbars-and-other-screen-menus.md](doc/en/wasm/dev/adr/0179-per-screen-taskbars-and-other-screen-menus.md))
- **Drag a window to another screen.** Drag a window by its title bar onto another screen; an outline shows where it will land. ([#238](https://github.com/Kazo-ca/Os/pull/238), [0183-drag-a-window-between-screens.md](doc/en/wasm/dev/adr/0183-drag-a-window-between-screens.md))
- **Install apps from GitHub with hackpkg.** The hackpkg command installs, updates and removes an app from its GitHub repository. App authors build the .hackapp package with HackerOsPack. ([#238](https://github.com/Kazo-ca/Os/pull/238), [0182-install-apps-from-github.md](doc/en/wasm/dev/adr/0182-install-apps-from-github.md))
- **Mount a computer folder as a network drive.** In Chrome and Edge, a folder of your computer can be mounted under /mnt and used like any other drive, with the mount and umount commands. ([#238](https://github.com/Kazo-ca/Os/pull/238), [0181-host-folder-mounted-as-a-network-drive.md](doc/en/wasm/dev/adr/0181-host-folder-mounted-as-a-network-drive.md))
- **Settings ▸ Screens.** A new Settings page lists your screens, opens or closes them, restores them after a restart and remembers where each one goes. ([#238](https://github.com/Kazo-ca/Os/pull/238), [0180-screen-service-placement-and-memory.md](doc/en/wasm/dev/adr/0180-screen-service-placement-and-memory.md))
- **Use several screens.** Extend HackerOS to other monitors: each screen gets its own desktop, and windows move from one screen to another. ([#238](https://github.com/Kazo-ca/Os/pull/238), [0178-extended-screens-in-display-surfaces.md](doc/en/wasm/dev/adr/0178-extended-screens-in-display-surfaces.md))
- **New Folder button in folder dialogs.** The Choose folder and Save dialogs have a New Folder button, also used by Open Folder in Code Editor. ([#218](https://github.com/Kazo-ca/Os/pull/218), [0175-new-folder-in-the-choose-folder-dialog.md](doc/en/wasm/dev/adr/0175-new-folder-in-the-choose-folder-dialog.md))
- **Cursor themes.** Settings ▸ Appearance ▸ Cursors changes the pointer of the whole OS: System (the device's cursors), HackerOS Neon, Gothic Crimson, or your own theme, a folder of PNG cursors with their hot spot in ~/.config/hackeros/cursors/ or /etc/hackeros/cursors/. Apps need no change. ([0205-cursor-themes.md](doc/en/wasm/dev/adr/0205-cursor-themes.md), [cursor-themes.md](doc/en/wasm/framework/cursor-themes.md))
- **Hack Store: apps open without a restart, signed packages, safe installs.** An app installed or updated opens at once when it was not already loaded. Packages from a source with a signing key are verified before install. Installs are transactional: an interrupted one is finished or undone at the next start, and hackpkg repair fixes the rest. The previous version is kept: Go back to in the Store or hackpkg rollback. The app's settings and data are backed up before its first start in a new version. ([0214-hack-store-hot-add-signing-transactions.md](doc/en/wasm/dev/adr/0214-hack-store-hot-add-signing-transactions.md), [app-installation.md](doc/en/wasm/dev/app-installation.md))
- **Hack Store: browse, install and update apps in one click.** The Hack Store is pinned in the Start menu on desktop and mobile. It lists the apps of the reviewed catalogs by category, searches them, shows each app's page (screenshots, description, size, license, capabilities, trust), installs it for you or for everyone, opens, updates and uninstalls it, and offers Restart to finish. It checks for updates at sign-in then every 6 hours, and says what it finds in a notification. hackpkg install <appId> installs from the same catalogs, and asks you to choose with catalog:<name>/<appId> when several list the app; the SDK gains HackAppPackages.GetCatalogsAsync, GetUpdatesAsync and RestartToFinishAsync. ([0212-hack-store-app-build.md](doc/en/wasm/dev/adr/0212-hack-store-app-build.md), [0215-hack-store-answers-notification-and-ambiguous-app-id.md](doc/en/wasm/dev/adr/0215-hack-store-answers-notification-and-ambiguous-app-id.md), [app-installation.md](doc/en/wasm/dev/app-installation.md))
- **Icon packs.** Settings ▸ Appearance can replace the app and file icons with a PNG icon pack. The new Néon pack is included, and packs are read from /usr/share/icons and ~/.local/share/icons. Open windows, the Start menu, the desktop and the File Explorer change their icons at once. ([0203-icon-packs.md](doc/en/wasm/dev/adr/0203-icon-packs.md))
- **Image wallpapers.** Settings ▸ Appearance ▸ Wallpaper puts a PNG, JPEG or WebP image on the desktop: one of the 4 wallpapers shipped with HackerOS, an image of /usr/share/hackeros/wallpapers or ~/.local/share/hackeros/wallpapers, or any image picked with Browse. With several screens, each screen can have its own. Fit chooses fill, fit, stretch, center or tile. ([0202-desktop-wallpaper-images.md](doc/en/wasm/dev/adr/0202-desktop-wallpaper-images.md))
- **Install apps for yourself, trusted sources and block list.** An app from a trusted source is now installed for you alone, without an administrator. An install for every user, an untrusted source or an app of the administrator's block list asks every time for an administrator sign-in, then a window that shows the app, its source, its trust level and its capabilities. Administrators manage the sources and the block list in Settings > Sources and block list or with hackpkg sources and hackpkg policy. hackpkg gets --user and --system; --allow-untrusted is gone. ([0208-hack-store-sources-trust-build.md](doc/en/wasm/dev/adr/0208-hack-store-sources-trust-build.md), [app-installation.md](doc/en/wasm/dev/app-installation.md))
- **Installed apps load their images, scripts and workers.** An app installed with hackpkg now finds the files of its wwwroot/ folder at the same address as an app built into the OS: images, scripts, style sheets, Web Workers and the scripts those workers load. An app that wraps a JavaScript project works once installed. ([0206-serve-installed-app-assets.md](doc/en/wasm/dev/adr/0206-serve-installed-app-assets.md))
- **See what's new since your last visit.** Settings ▸ What's new lists the changes of each version with a New badge on the ones you have not seen. After you sign in, a notification tells you how many there are, and a dot on the Start button stays until you have seen them. ([change-list.md](doc/en/wasm/dev/change-list.md))
- **Theme packs in the Hack Store.** The Hack Store has a Themes tab. A .hacktheme pack brings themes, wallpapers, icons, sounds and cursors; install it for yourself without an administrator, or for everyone with the two-step approval, then pick its parts in Settings ▸ Appearance. A pack holds no code: no SVG, no remote address, and every file is checked against the SHA-256 of its manifest. Apps reach packs through HackAppPackages.InstallThemePackAsync, GetInstalledThemePacksAsync and RemoveThemePackAsync. ([0213-theme-packs-build.md](doc/en/wasm/dev/adr/0213-theme-packs-build.md))
